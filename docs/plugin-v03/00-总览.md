# v0.3 插件化设计 · 00 总览

> 状态：**设计稿待审核**（未实施）。本文是套件入口；逐篇展开见同目录 01–08。
> 事实基线：v0.2（commit ed3ac19）。所有"现状"均经代码核实，引用 `文件:行号`。

## 一、要解决什么

现有各板块能力齐全但**接线硬编码**：加一个搜索源、一种出图格式、一个 Agent、一块设置面板、
一类剧情上下文，都要改编排本体（agent_graph 3563 行）或多处分发点。v0.3 的目标不是重写，
而是把「接线」从「核心」里拆出来，变成**注册 + 贡献**：

- 核心只保留：调度内核（supervisor 路由 + 图执行）、回合事务（roleplay_turn）、
  安全闸门（capability_sandbox / instruction_provenance）、wire 协议（chat_stream_protocol）、
  持久化真源（chat_snapshot / generation_store / 各 store）。
- 其余一切——预设、正则、剧情推进各阶段、生图/视频/音频渲染、对话 UI、画布 UI、
  工具、Agent——都是**插件**：内置插件随源码发布（编译期注册），用户插件落数据目录（运行期注册）。

对标 DeepSeek Harness「everything is a plugin」，但按本项目的合同风格落地：
**约束优先落为注册表 schema、import-linter 合同、manifest 门禁和双端测试，不写提示词约束。**

## 二、插件分类学（7 类贡献，一张表说完）

| # | 插件类型 | 对应用户 named | 现状底座 | 目标形态 |
|---|---------|---------------|---------|---------|
| 1 | **数据插件**（data pack） | 预设插件、正则插件 | `preset_store` / `regex_store` 已是文件真源，热读已成立 | 预设/正则/卡/世界书打包为带 manifest 的包，安装即落盘，零代码 |
| 2 | **能力插件**（capability） | （工具子集） | `capability_registry` 15 条 + manifest --check + sandbox 两档租约 | 内置显式注册不变；外部插件从 `DATA_DIR/plugins/*.py` 加载注册，默认低权限 |
| 3 | **Agent 插件**（agent） | 剧情推进插件（Agent 面） | `agent_plugins.py` 10 内置 + `load_user_plugins`（只覆盖元数据） | route→节点实现一起注册；每个 Agent 声明可见工具子集与模型偏好 |
| 4 | **媒体插件**（renderer） | 生图/视频/音频插件 | renderer 注册表只有图片两格式；视频/音频走协议同构但无注册表 | 统一三媒体 `MediaRenderer` 注册表；触发判定仍归核心纯逻辑 |
| 5 | **管线插件**（turn stage） | 剧情推进插件（链路面） | `TurnExecutionHooks/TurnFinalizationHooks` 是雏形；阶段 B 注入与维护顺序硬编码 | 组装/写回/维护三段 Stage 注册表 + TurnLedger 显式轮间数据 |
| 6 | **视图插件**（view） | 对话模型 UI 插件、画布模式 UI 插件 | AppBody if 链 + SettingsView NAV 数组；无注册表 | ViewRegistry + 声明式 UI 贡献；外部插件前端只做声明，不带任意 JS |
| 7 | **循环插件**（agent loop） | （roadmap 第 3 步） | `fabric_loop.run_loop` 单实现 | AgentLoopProvider 抽象，默认循环 = fabric_loop |

一个插件可同时贡献多类（剧情推进插件 = Agent 插件 + 管线插件 + 绑定 UI 贡献）。
**manifest 一个，贡献点若干**（见 01）。

## 四、核心不变量（全部篇目共同遵守，违反即设计错误）

1. **内核不下放**：路由安全校验（`_route_available`）、能力授权（`capability_sandbox.authorize`）、
   wire 版本化、快照真源，永远在核心。插件只能**贡献**，不能**改写**闸门。
2. **缺插件 = 降级，不是报错**：沿用「无卡 → deps=None 整条能动性子图静默降级」的既有语义
   （agent_graph.py:999）。每个注册点必须有"缺席"分支，核心在零插件时行为 = v0.2。
3. **行为不变迁移**：M0–M4 每步完成后，现有测试全绿、现有默认行为逐字节不变。
   内置插件化 = 把现有代码搬进注册调用，不是重写。
4. **单一属主不稀释**：每类贡献点只能有一个注册表属主模块；禁止插件互相 import 对方内部，
   只许经注册表与 TurnLedger 键通信。
5. **外部不可信**：用户插件默认低权限（复用 instruction_provenance 概念），不得扩大
   工具/文件/联网/安装权限，不得覆盖审批与安全规则（承接 ROADMAP-PLUGIN-V03 红线）。
6. **密钥边界不变**：密钥只进 gitignored 的 user_state.json；插件声明需要的模型档位
   （needs_model），经核心取用，不得直接读密钥文件。

## 五、与用户 named 插件的映射（验收视角）

- **预设插件** → 05 篇：预设包 = preset.json + 思维链 + 配套正则 + 可选世界书/卡，一键装。
- **正则插件** → 05 篇：正则脚本包（placement 1/2/5/6/7），装后全局/卡/预设三源合并处按包注入。
- **剧情推进插件** → 02 篇（主战场）：角色卡/世界书/仓库绑定按钮 + 剧情推进整条链
  （组装→生成→写回→维护）全部 Stage 化；「添加绑定」= 插件声明 BindingContribution。
- **对话模型 UI 插件** → 04 篇：ChatView 注册为内置视图插件；外部可注册消息 part 渲染器、
  输入区按钮、面板卡片（声明式）。
- **画布模式 UI 插件** → 04 篇：CanvasStageFlow 同上；画布节点类型注册表化。
- **生图/视频/音频插件** → 03 篇：MediaRenderer 注册表统一三媒体。
