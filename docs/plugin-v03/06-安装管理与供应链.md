# v0.3 插件化设计 · 06 安装管理与供应链

## 一、安装来源与事务

| 来源 | 形态 | 处理 |
|------|------|------|
| 本地文件 | zip / 目录 | 直接走安装事务 |
| URL 下载 | 受控下载 | 复用 `model_downloader` 事务（临时文件 → sha256 → 落盘），来源记 provenance |
| 内置市场（远期） | 索引 + 包 | 索引只读公开清单，安装仍走同一事务；v0.3 不承诺 |

**安装事务（`plugin_install.py`，单一属主）**：

```text
receive → parse manifest → api_version 校验 → 结构校验（数据包禁代码 / 代码包入口可导入）
        → sha256 全文件校验 → 权限解析（空默认 + 声明清单）→ 【用户确认权限】
        → 落盘 DATA_DIR/plugins/<id>/ → 登记 installed.json（含 hash/来源/时间）
        → 注册表加载 → 设置页可见
失败任何一步 → 删临时目录 + 删半包，已注册贡献点回滚（幂等 unregister）
```

- 权限确认 UI（设置页「插件」面板）：逐条列权限词的**人话解释**（capability/turn_stage/
  data 域/模型档位），高危项（run_shell、file.write_text、联网）单独红字确认。
  对应 ROADMAP 红线「外部插件默认低权限，不得覆盖审批与安全规则」。
- 升级 = 同 id 新版本走同一事务，文件替换前备份旧 manifest；api_version 不匹配拒升。
- 卸载/禁用见 05 篇（数据包）与 01 篇（通用四态）。

## 二、信任与哈希

- `installed.json` 记录：id/version/sha256(逐文件)/来源 URL 或 "local"/安装时间/启用人。
- `source=external` 的插件自动叠加 `instruction_provenance` 低权限标记于其自带提示词；
  设置页显示 `external_unreviewed` 徽标（沿用 Smithery 技能既有语义）。
- 不做签名体系（v0.3 明确不承诺 Artifact Trust，与 ARCHITECTURE.md:348 口径一致），
  只做**哈希记录 + 来源透明 + 权限最小化**三件实事；manifest expected-hash 强制比对
  只对"从索引安装"的远期形态生效。

## 三、运行期隔离（现实边界，如实声明）

后端插件代码运行在**同一进程**，隔离手段是结构性的而非进程级的：

1. 权限声明制 + 注册期校验（拿到什么能力是静态可见的）；
2. 所有能力执行仍过 `capability_sandbox.authorize`（租约/路径域/审批不豁免）；
3. `project.run_shell` 类高危能力对外部插件**默认拒绝**，白名单开启需显式确认；
4. run_trace 新增 `plugin.*` 事件（load/enable/disable/call），插件发起的能力调用
   在 Trace 带插件 id——出问题可归因；
5. 单插件异常不倒核心：装载期逐插件 try，执行期能力调用本就有逐条失败隔离。

进程级沙箱（子进程/容器）是 roadmap「沙箱 provider 抽象」的后续形态，v0.3 只把
capability_sandbox 的租约 API 保持为唯一执行闸门，未来换沙箱 provider 不动插件合同。

## 四、CLI（可选，低优先）

`dsh plugin list/enable/disable/install/remove`（复用后端 services，纯本地操作）。
设置页 UI 优先；CLI 只服务 headless 场景，不做联网市场。
