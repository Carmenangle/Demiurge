# v0.3 插件化设计 · 05 预设与正则数据插件

> 数据插件 = 零代码、纯资源包。这一类成本最低、收益最直接，也是插件安装管理的第一个消费者。

## 一、现状底座（都已是文件真源 + 热读）

- **预设**：`preset_store` 是偏置预设单一属主（ST OpenAI 预设解析、`assemble_messages`
  多消息通道、`select_chains` 按真状态选思维链、宏替换）；落盘 `presetDir/<安全名>.json`，
  **热读已成立，纯数据改动无需重启**（ARCHITECTURE.md:108）。
- **正则**：双 runtime 合同——后端 `regex_engine`（存储/发送档）+ 前端 `lib/regexEngine.ts`
  （显示档），同逻辑两实现，**有意不合并**；来源三路合并：全局 `data/regex_scripts.json`
  （`regex_store`）→ 激活预设 → 当前卡内嵌（ARCHITECTURE.md:555）。
- **角色卡**：`character_store` 一张卡=一个文件夹（卡本体/内嵌世界书/正则/头像/表情同处）。
- **外部资源归一入口已存在**：`edit_import_adapter` 把外部 JSON（纯卡/内嵌拆侧车/独立世界书/
  预设剥鉴权/正则补 ID 编译校验）确定性转换——**包安装就是复用这条归一管线**。

## 二、包格式（DataPack）

```text
<pack-id>-v1.2.0.zip
├─ plugin.json            # manifest：kind=data_pack, pack_type, 声明 permissions:data:*
├─ pack.json              # 资源清单：文件列表 + sha256 + 目标域
└─ assets/
   ├─ preset/GrayWill.json          # presetDir 落盘（ST 格式或 Demiurge 归一格式）
   ├─ regex/*.json                  # regex_store 全局档（ST 格式数组）
   ├─ worldbook/*.json              # 独立世界书
   └─ characters/<卡名>/…           # 归一化卡文件夹
```

- **安装事务**：解压到临时目录 → 逐文件 sha256 校验（复用 `model_downloader` 的
  临时文件+校验+落盘事务形态）→ `edit_import_adapter` 归一校验（正则编译、预设剥鉴权、
  卡扁平化）→ **不覆盖已存在同名资源**（与该 Adapter 的默认拒绝覆盖合同一致）→
  落盘 + 注册表登记。任何一步失败整体回滚，不留半包。
- **热读**：preset/regex 天然热读；卡/世界书包落盘后前端刷新资产列表即可。
- **卸载**：只删本包 manifest 记录的文件清单（pack.json 是卸载真源），禁止递归删目录；
  用户改过的资源（如手动编辑过的预设）卸载时提示保留。
- **启用/禁用**：正则包禁用 = 合并源里按包过滤（`_resolve_regex_scripts` 三路合并处
  按 pack 标签过滤，一处改动）；预设包禁用 = 预设选择器隐藏（资源不删）。

## 三、边界

- 包内资源只落白名单域（presetDir / regex / 独立世界书 / 角色卡库），manifest 声明
  `permissions:data:<域>`，越界拒装（01 篇权限表）。
- 包**不含代码**：发现 `.py`/`.js` 文件即拒装（供应链红线）。
- 正则 placement 扩展（如新增 placement 8）属核心 API 变更，插件不得私自定义 placement。
- 预设包内 `regexScripts` 兼容 Demiurge 根键与 ST `extensions.regex_scripts` 双位置，
  编辑写回原位置（既有单一真源合同不变）。
- 密钥剥离在归一管线内强制（`edit_import_adapter` 既有职责），安装时二次校验。

## 四、为什么先做这一类

数据插件把「安装事务 / manifest / 权限 UI / 启停 / 卸载」整条管理链路先跑通，
且风险面最小（无代码执行）；M5 的代码插件加载器直接复用 M2 建好的管理壳。
施工顺序见 07 篇。
