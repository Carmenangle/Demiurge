# v0.3 插件化设计 · 07 迁移路线与回归门禁

## 一、里程碑总览（每步独立提交、独立可回滚、行为不变）

```text
M0 注册表统一与门禁      （1-2 天级）  地基，零行为变化
M1 工具子集              （小）        AgentPlugin.tools
M2 媒体 renderer 统一    （中）        三媒体注册表化——用最小风险面验证"注册表化"方法论
M3 前端视图注册表        （中）        AppBody/Settings/消息part/画布节点/输入动作
M4 剧情推进管线化        （大，四步）  TurnLedger → assemble → writeback → maintenance → 绑定UI
M5 动态能力插件+循环provider （中）    外部代码插件加载、AgentLoopProvider、模型偏好
M6 安装管理与数据包      （中）        安装事务、权限UI、预设/正则包
```

排序理由：M2/M3 先行建立「注册表化 + 门禁」的肌肉记忆并快速兑现用户可感的扩展点
（新搜索源/新出图格式/新面板）；M4 是最大重构放在方法论验证之后；M5/M6 依赖
M0 的 PluginRegistry 与 M2 的管理壳。

## 二、逐步验收

### M0 注册表统一（01 篇落地）
- `plugin_runtime.py` + PluginManifest + builtin_plugins 包骨架；三既有注册表挂到统一装载器。
- 新 import-linter 合同（plugin_runtime 方向 ×2）+ plugin manifest 生成/`--check` 进 CI。
- 验收：后端全量测试绿，现有 agent_plugins.json 双读兼容测试，CI 含新门禁。

### M1 工具子集
- AgentPlugin 加 `tools: list[str]`；`route_available` 过滤工具面；10 内置插件声明子集
  （剧情=无 shell/file.edit；智能编造=全量）。
- 验收：路由单测矩阵扩 tools 维度；fabric_loop 收到越权能力被拒的负路径测试。

### M2 媒体统一（03 篇施工清单）
- `media_renderers.py` 属主 + 5 内置项 + `_build_renderer` 改读注册表 + deprecated 别名。
- 验收：插画/视频/音频既有回归全绿；测试内注册假想供应商完成"只写一个文件"验收。

### M3 前端注册表（04 篇施工清单）
- viewRegistry/settingsPanelRegistry/消息part/画布节点/输入动作五个注册面。
- 验收：`npm test`/`npm run build` 绿；bundle 首屏 ≤300kB 基线不涨；四档视口回归。

### M4 剧情推进管线化（02 篇 M4.1–M4.6）
- 每小步验收已在 02 篇列明；全程 Trace 键不变、默认行为逐字节不变。
- 额外固化：**维护顺序拓扑断言测试**（表格→纪要→Curator 的依赖由 requires 推导，
  测试断言拓扑序而非实现顺序——防未来回归）、Stage 缺席降级测试、Ledger 越权读写负测试。

### M5 动态能力插件 + 循环 provider
- 外部 `.py` 能力插件（ROADMAP 第 2 步）：低权限默认、source 标记、manifest --check 扩展。
- AgentLoopProvider（ROADMAP 第 3 步）：`run_loop` 签名即接口，默认实现 = fabric_loop；
  plan_compiler_node 按 AgentPlugin.loop 选择。
- 模型偏好（ROADMAP 第 4 步前半）：AgentPlugin.model_pref → supervisor/执行取模型时归口。
- 验收：恶意插件样本测试（越权注册/越权能力/import 逃逸尝试）全部拒载。

### M6 安装管理与数据包（05/06 篇）
- 安装事务 + 权限确认 UI + 预设/正则/卡包；卸载不删用户改过的资源。
- 验收：安装失败回滚不留半包；坏包（含 .py 的数据包、哈希不符、越界落盘）全部拒装；
  装一个真实预设包端到端可用。

## 三、全程持续门禁（不因插件化放松任何现有红线）

| 门禁 | 插件化增量 |
|------|-----------|
| pytest 双端 + Playwright | 每步全绿是合入条件；新增负路径测试（拒载/降级/越权） |
| import-linter | +2 合同（plugin_runtime 方向）；现有 17 条不动 |
| manifest --check | capability 既有 + plugin manifest 新增，双 --check 进 CI |
| mypy / ruff / 硬编码检查 | 照旧；插件文件进 mypy_files.txt |
| bundle 体积 | 首屏 ≤300kB 合同照旧；注册表本身零运行时依赖 |
| 发布门禁 release_preflight | DATA_DIR/plugins 属运行态，天然不进发布包（验证一条用例） |

## 四、回滚策略

每个 M 步独立提交；M4 四小步各自独立。任何一步出现不可收敛缺陷：
revert 该步即可回退——因为每步完成后核心对插件的依赖只有「读注册表」一个方向，
注册表空转 = 回到上一步行为（降级不变量保证）。
