# v0.3 插件化设计 · 08 红线与风险

## 一、红线（承接 ROADMAP-PLUGIN-V03，逐条给出 enforcement 点）

| 红线 | enforcement |
|------|-------------|
| 外部插件默认低权限，不得扩大工具/文件/联网/安装权限 | manifest 权限声明制 + 注册期校验 + sandbox.authorize 不豁免 + 高危能力默认拒绝（01§五、06§三） |
| 不得覆盖审批与安全规则 | 审批闸门/路由校验/wire 版本在核心（00§四不变量 1）；writeback 失败关闭语义不可被 Stage 绕过 |
| manifest / 注册表防漂移门禁保持 | plugin manifest --check 与 capability manifest --check 并行进 CI（07§三） |
| 密钥只走 user_state.json | 插件经 needs_model 声明模型档位由核心供给；run_trace 脱敏继续覆盖 plugin.* 事件 |
| instruction_provenance 权威限制继续适用 | 插件自带提示词/技能文本自动叠低权限标记（06§二） |
| 自动视频永不默认 / 触发策略归核心 | 插件只注册渲染能力不注册触发策略（03§二） |
| 媒体不回灌 token / 单一媒体通道 / slot 原位回填 | 03§四禁止清单；协议层零改动 |
| 场景插画纯逻辑合同（scene-illustration-purity 等 import-linter 合同） | 不动；renderer 搬家后纯度合同重新指向新属主 |

## 二、风险与兜底

| # | 风险 | 概率/影响 | 兜底 |
|---|------|----------|------|
| 1 | **剧情链拆不净**：1600 行 roleplay_node 内 ctx 隐式约定比探查所见更多，搬家时漏搬 | 中/高 | M4 采取「机械搬家不改逻辑」纪律 + Trace 键不变验收 + 每小步独立提交可回滚；拆不动的一段**允许留在核心**（诚实的半插件化好过坏拆），在 02 篇映射表标注遗留 |
| 2 | **注册表性能**：每回合遍历 Stage/渲染器 | 低/低 | 全部为内存 dict，规模个位数到两位数；无 IO；不需要缓存层 |
| 3 | **TurnLedger 变成垃圾桶**：键无限增长、插件乱写他人键 | 中/中 | 键注册制（owner+schema）+ 越权校验负测试 + Trace 归档可见；不提供"匿名键" |
| 4 | **前端 bundle 膨胀**：注册表化过程顺手加功能 | 中/中 | M3 验收含体积基线；外部插件零 JS 的决策本身就是体积保险 |
| 5 | **兼容债**：旧 agent_plugins.json / deprecated register_renderer 别名拖着不走 | 高/低 | 每个兼容项在 07 篇登记废弃版本；一个版本周期后删除并出 release note |
| 6 | **第三方 Stage 破坏回合事务**：写回段吞异常/乱发事件 | 中/高 | WritebackStage 契约是纯变换（TurnFinalization→TurnFinalization），事件发射面只在核心 emit 槽；异常语义按段类型固定（02§三）不提供可配置吞异常 |
| 7 | **重构期间双轨漂移**：Stage 化后有人回 roleplay_node 加逻辑 | 中/中 | M4.5 完成后删除旧键旧代码（不留双轨）；import-linter + 测试拓扑断言把「必须走注册表」锁死 |
| 8 | **安装包供应链**：恶意包提示词注入/资源投毒 | 中/中 | 归一管线剥鉴权 + 哈希记录 + provenance 低权限标记 + 检索文本不可信输入既有合同（ROADMAP 排雷第 6 条）；v0.3 不承诺签名，如实声明边界 |
| 9 | **范围蔓延**：想一步到位把 supervisor/comfyui_client 也插件化 | 高/中 | 明确不做清单（下节）；roadmap 第 1-6 步之外的新想法进 v0.4 讨论 |

## 三、明确不做的（v0.3 边界，防蔓延）

- **supervisor 路由逻辑不插件化**：路由界限（强命令层/三轴判别）是安全面，保持核心单测矩阵。
- **roleplay_turn 回合事务不插件化**（只有三 hook 槽）。
- **进程级沙箱/容器**不做，只保租约 API 为未来 provider 接口。
- **签名体系 / 在线市场**不做，只做哈希+来源+权限三件实事。
- **外部插件的任意前端 JS** 不做（声明式 ui_decl 是唯一通道）。
- **跨插件直接 import** 不做（只经注册表与 Ledger 键）。

## 四、审核检查单（给审核者）

1. 00§四 六条不变量是否认账？尤其「缺插件=降级」与「行为不变迁移」。
2. 02 篇 M4.1–M4.6 的拆解粒度是否同意？「拆不净的一段允许留核心」的兜底是否接受？
3. 03 篇「插件只注册渲染、不注册触发」的边界是否同意？
4. 04 篇「外部插件前端只做声明式 ui_decl、零任意 JS」是否接受？
5. 07 篇里程碑排序（M2/M3 先于 M4）是否同意？
6. 08§三 不做清单是否有必须加入 v0.3 的遗漏？
