# v0.3 插件化设计 · 03 媒体插件（生图 / 视频 / 音频）

## 一、现状事实

- **图片**：renderer 注册表在 `scene_illustration.py:594-608`（纯 dict + register/get/available），
  接口 `Renderer = Callable[[SceneRequest], str]`；实现为工厂闭包
  （`cloud_renderer(cfg)` / `comfy_renderer(cfg)`，scene_renderers.py:65/:93），
  由 `agent_graph._build_renderer`（:2241-2264）按 ctx 接线，**不走 register_renderer**。
- **视频**：云端 `video_gen.py`（文生/图生，轮询 5 分钟）+ 前端 ComfyUI 视频模板路径
  （smartVideo + comfy_video 开关 + motion 门限），回填走 media-slot；后端无 video-submission 端点。
- **音频**：无合成服务，协议层已就位——`audio_dialogue_extract.py` 从正文 `<audio>` 块提取
  台词+IndexTTS 八维情感向量 → `audio_request` 事件 → 前端驱动 ComfyUI 音频工作流 →
  `audio_merge.py` ffmpeg 拼接落盘。
- **wire 已同构**：media-slot kind ∈ image/video/audio（chat_snapshot.py:454-456），
  15 种流事件含 image/video/illustrate_request/audio_request。**协议层不需要任何改动。**

## 二、设计：MediaRendererRegistry（三媒体统一）

```python
# services/media_renderers.py（新属主；scene_illustration 的 renderer dict 并入后删除）
MediaKind = Literal["image", "video", "audio"]

@dataclass(frozen=True)
class MediaRendererSpec:
    kind: MediaKind
    format: str                    # 如 "comfyui" | "gpt-image" | "cloud-video" | "indextts"
    factory: Callable[[MediaConfig], MediaRenderer]   # 工厂闭包，沿用现状形态
    sync: bool                     # sync=云端同步出图返回地址；async=发槽事件前端守望
```

- **接口统一为** `MediaRenderer = Callable[[MediaRequest], MediaOutcome]`：
  image 现状返回地址字符串 → 包装为 `MediaOutcome(url=...)`；video/audio 返回任务引用或地址。
  `MediaRequest` 按 kind 判别（image=SceneRequest 超集；video=video_request；audio=audio_request）。
- **触发判定不上移**：`scene_illustration.decide_trigger`（图片触发纯规则）、
  「自动视频永不默认」「音频按 comfy_audio 开关」继续归核心纯逻辑（ROADMAP 多模态排雷合同
  第 1、2 条）。插件只注册**渲染能力**，不注册**触发策略**——这保持了
  「renderer 不拥有触发」「scene_illustration 不拥有出图」的既有禁止反向合同。
- **sync/async 分流保持现状**：图片 ComfyUI=async（槽事件），云端=sync；
  视频全部 async；音频按现状前端驱动。插件声明 sync 属性，核心按属性走对应通道，
  生成通道隔离不变（ComfyUI FIFO 不占 Agent 通道）。

| 内置插件 id | kind | format | 来源（搬家） |

迁移要点：M2 只做「把三媒体现状注册进统一注册表 + `_build_renderer` 改读注册表」，
不改任何请求/回填协议。`scene_illustration.register_renderer` 保留一个版本周期作
deprecated 别名（转发到新注册表），其后删除。

## 四、第三方媒体插件能做什么 / 不能做什么

**能做**：注册新的云供应商 renderer（如新的视频 API）、新的本地管线格式；
声明 needs_model 与代理需求（proxyMode 既有三态合同）；带配置面板卡片（04 篇 ui_decl）。

**不能做**：
- 改触发策略（何时出图/出视频）与分级判定（nsfw/climax 保守规则在核心）；
- 修 media-slot 协议或新建第二套媒体通道（SSE/快照/恢复/瘦身全复用现有合同）；
- 让图片/视频 token 回灌对话历史（url+caption 红线，ROADMAP 排雷第 9 条）；
- 改 `messageId+slotId` 原位回填与 claim 原子语义（generation_store 既有闸门）。
