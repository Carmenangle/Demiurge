## 一、现状事实

- **分派是 if 链**：AppBody.tsx（254 行）17 个 React.lazy + if/return 链；
  新增视图要同时改 `viewRouting.ts`（View 类型/SIMPLE_VIEWS/NAV 数组）+ AppBody lazy 块 +
  App 导航——「注册表化尚未成形」（探查确认）。
- **设置页是数组+条件渲染**：SettingsView.tsx NAV 数组 + 9 个面板各一个文件，
  加板块 = NavId + NAV 项 + Panel 文件 + 一行条件渲染——半成品注册表。
- **画布是内容区切换**：ChatView 内部 contentView 状态（chat/canvas，按作品记忆
  `laf_view_<workId>`），CanvasStageFlow.tsx 3400 行 + `canvasRuntime/canvasLayout` lib。
- **前端无任何组件注册表先例**。

## 二、设计：ViewRegistry

```ts
// lib/viewRegistry.tsx（新属主）
export interface ViewContribution {
  key: string;                       // 对应 hash 段
  entry: React.LazyExoticComponent;  // 代码级插件 = 内置 lazy 块
  nav?: { section: NavSection; label: string; icon?: string; order: number };
  requiredPermission?: string;       // 与后端权限词对齐（禁用插件隐藏入口）
}
registerView(v: ViewContribution)    // AppBody 渲染 = registry.get(viewKey) ?? Home
```

- **AppBody if 链 → 注册表循环**：`viewRouting.ts` 的 View 联合类型扩为开放 string +
  `KNOWN_VIEWS` 常量（类型收窄帮助保留）；AppBody 只剩「查注册表 → Suspense 渲染」。
  React.lazy 边界与首屏 ≤300kB 预算合同不变（ARCHITECTURE.md:157）。
- **对话/画布 = 内容级视图贡献**：ChatView 与 CanvasStageFlow 注册为内置视图插件
  （`view:chat`、`view:canvas`）；`contentView` 切换按注册表 + 作品记忆键解析——
  这就是「对话模型 UI 插件 / 画布模式 UI 插件」的内置形态。二者都是**源码内代码**，
  走正常构建、测试与 bundle 门禁。

## 四、外部插件的前端边界（关键安全决策）

**外部插件不加载任意 JS。** 前端进程无沙箱，任意外部代码等于放弃 XSS/供应链全部防线。
分级：

- **内置视图插件**（ChatView/Canvas/各 Panel）：源码内代码级，编译期注册，全量门禁。
- **外部插件前端贡献**：只有 `ui_decl` 声明式（JSON）——导航项、设置卡（表单字段声明：
  key/label/widget∈text|number|select|toggle/path/模型选择/文件选择）、面板卡片文案、
  绑定字段、输入区按钮（指向系统能力或后端能力 operation）。渲染器是**通用表单/卡片
  组件**，吃声明渲染结果；声明大小上限（如 32KB），未知 widget 拒绝渲染。
- 外部插件需要真交互逻辑 → 写后端能力插件（capability），前端声明一个按钮调它。
  这与「路由薄、服务深」同构：**前端薄、后端深**。
