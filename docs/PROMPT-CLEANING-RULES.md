# 通用提示词清洗规则（共享 · 单一事实来源）

> 用途：所有生成模态（图像 / 视频 / 音频等）在「剧情正文 → 最终提示词」之间的
> **共享清洗链**。任何模态都遵循这一份规则，不各自为政，节省上下文、保证防拦截一致。
> 代码实现：`backend/app/services/prompt_clean.py`（纯函数，0 I/O、0 LLM）。
> 本文件是规则的**权威描述**；代码与文档不一致时以文档为准并修代码。

---

## 1. 为什么需要清洗

剧情正文是**叙述性文本**：带防拦截拆字标记（`@()@`）、混杂修饰/心理/对白、不直接是
客观画面。而生成模型（图像 / 视频）吃的是**客观、干净、按目标语言组织**的提示词。
清洗链做三件事：**还原**（去掉防拦截标记）→ **提取**（客观画面事实）→ **拼装**（目标语言）。

清洗不是审查；它保留原义，只去掉「防拦截外壳」和「叙述杂质」，让提示词可被模型执行。

---

## 2. 清洗链（四步，按序）

### 2.1 破甲还原（防拦截外壳）

正文生成时"已过甲"（带 `@(x)@` / `(x)@` / `@(x)` 拆字包裹），用于绕过文本内容审查。
提交给生成模型前必须还原成正常文字，否则标记残留会污染提示词。

正则（对齐用户给定 `/@\(([^()]*)\)(?=@)|@\(([^()]*)\)|\(([^()]*)\)@|@/g` → `$1$2$3`）：

```
@(温)@知夏  →  温知夏
(米)@色     →  米色
@(馆)       →  馆
裸 @         →  删除
```

实现：`prompt_clean.restore_jailbreak(text)`（含 `restore_jailbreak_with_offsets` 提供逐字偏移，供溯源）。
`i/<i>` 等分隔符由用户在各 placement 正则里另行配置，本规则只兜底 `@` 系。

### 2.2 可见正文（剥控制块）

只保留用户可见剧情：剥掉 `<think>` / `<content>` / `<status>` / `<表格更新>` 等控制块。
（`image_prompt_extract.visible_narrative_text` 已实现，各模态复用；视频锚点提取
`story_frames` 已用它。）

### 2.3 客观内容提取（叙述 → 画面事实）

从叙述性文本里提取**客观画面事实**，与「修饰/心理/对白」分离：

| 事实类别 | 说明 | 示例 |
|---------|------|------|
| 角色外貌 | 稳定外貌（脸/发/体型/标志物） | 米色针织开衫+陶杯 |
| 当前服装 | 正文明确的当前穿着 | 全员日常私服 |
| 场景 | 地点/环境/光影 | 温暖小面馆内景，暖黄吊灯 |
| 动作 | 当下肢体动作（视频还有动态） | 抬眼笑、举杯 |
| 关系/情绪 | 人物关系与氛围基调 | 三人围坐、温情 |

提取原则（对齐 image_prompt_extract 的「硬事实锁 + 开放视觉槽」）：
- **硬事实锁**：在场人物、稳定外貌、正文明确的当前服装、动作、关系、地点、剧情结果
  ——必须逐项保留，禁止改写/省略。
- **开放视觉槽**：正文没规定的微动作、姿态、视线、镜头、构图、光影、天气、背景活动
  ——必须根据时间/地点/天气/情绪/处境**合理联想补全**，不得留空、不得用占位语、不得退回通用模板。
- **缺失硬事实补全**：生成完整画面所需但正文没给的（当前服装/具体动作/地点环境/人物位置），
  必须补一个具体答案并以现有上下文为依据。

### 2.4 拼装（按目标语言）

同一套事实，按目标模型的提示词语法拼装：

| 目标 | 连接方式 | 示例 |
|------|---------|------|
| booru 串（ComfyUI/标签系） | `, ` 连接 | `masterpiece, best quality, 1girl, ...` |
| 自然语言（gpt-image 等） | `. ` 连接连贯短句 | `A girl in beige cardigan. Warm noodle shop.` |
| H3 叙事（视频模型） | 中文七段式/精简段 | `使用视频模型生成，15 seconds，16:9，镜头运动=pan。` |

实现：`image_prompt_extract.assemble_prompt`（booru/自然语言）、`video_prompt.compile_*`（H3 叙事）。

## 3. 各模态落点（谁用这条链）

| 模态 | 入口 | 清洗内容 |
|------|------|---------|
| 图像 | `agent_graph` → `image_prompt_extract` | 破甲还原 + 客观提取 + booru/自然语言拼装 |
| 视频 | `video_prompt.build_video_request` → `_clean_spec` | 破甲还原（`prompt_clean.clean_spec_text_fields`）+ H3 拼装 |
| 首尾帧锚点 | `story_frames` | 可见正文（含破甲还原）→ 首/尾段画面 |
| 音频（未来） | 待接线 | 台词逐字（`audio_dialogue_extract` 已做破甲还原） |

**独立性保障**：清洗规则不属于任何单一 placement（不挂在 IMAGE_PROMPT 名下）。
即使 `IMAGE_PROMPT` 那套清洗规则被删除，图像提示词仍由本共享规则（`prompt_clean` +
`image_prompt_extract` 的提取链）庇护防拦截——`test_prompt_clean.py` 回归保证。

---

## 4. 防拦截两层（与清洗链的关系）

| 层 | 机制 | 归属 |
|----|------|------|
| 第一层 | 破甲还原 `@()@` → 正常文字 | `prompt_clean.restore_jailbreak`（共享） |
| 第二层 | 用户正则清洗（`_apply_regex`，任意 findRegex/replaceString/trimStrings） | 接线层，需 ctx；图像用 IMAGE_PROMPT placement，视频复用同套机制 |

第二层不是「只能洗 @()」——它是用户可配的任意正则（全局库/预设/卡内嵌三层来源）。
第一层才是硬编码兜底。两层都保证：**提交给生成模型前，提示词干净、无防拦截外壳**。
