# Demiurge 推广、README 与 v0.2 发布规划

本文供后续独立对话继续完善宣传文案、截图、教程和发布节奏。它不定义业务架构；业务真源仍是 `CONTEXT.md`、`ARCHITECTURE.md` 与 `docs/memory/`。

## 当前结论

- README 的首要职责是完成最基础的功能展示，并让新用户跑通第一条剧情与自动插画链路；宣传文案服从可上手性。
- v0.2 暂不创建标签或 Release。功能稳定、教程齐全、发布工作流预演成功后再发布。
- README 引用的最终截图由用户在功能完善后统一截取；当前临时截图不上传。
- 对外演示优先使用适合公开平台传播的剧情样例；项目支持的完整创作能力在功能文档中如实说明。

## README 要完成的用户任务

用户只阅读 README，应能完成：

> 下载或启动 → 配置对话模型与 ComfyUI → 创建大仓库和小仓库 → 绑定角色卡与世界书 → 创建工作流模板 → 同步并绑定 LoRA → 开始剧情 → 获得原位自动插画 → 查看数据表、纪要与资产。

## README 建议结构

1. 项目定位、适用人群和本地优先边界。
2. 45–90 秒主流程演示或动图。
3. 基础功能展示：剧情、角色/世界书、记忆/数据表、自动插画、工作流、资产与本地工具。
4. 系统要求与下载入口。
5. 五分钟快速开始。
6. 首次配置：对话模型、图像模型、ComfyUI、仓库文件夹、Embedding/Reranker。
7. 创建作品并绑定角色卡、世界书和人设。
8. 工作流模板、LoRA 和自动插画的最短可用教程。
9. 正确运行结果与常见错误。
10. 进阶教程索引、架构、数据安全、贡献和许可证。

## 详细教程目录

详细教程放入 `docs/tutorials/`。每篇统一包含：用途、前置条件、操作步骤、参数解释、正确结果、常见错误、排查入口。

### 1. 首次安装与模型配置

- Windows、macOS ARM64、Linux x64 的启动与停止。
- OpenAI 兼容对话接口、图像接口和代理配置。
- ComfyUI 路径与地址。
- 仓库文件夹、角色卡、世界书、预设和模型目录。
- Embedding 与可选 Reranker；未配置时的降级行为。

### 2. 大仓库、小仓库与作品绑定

- 创建大仓库与自动创建/选择小仓库。
- 绑定角色卡、世界书和用户人设。
- 开场角色、多角色出场、作品隔离与分支。
- 会话、生成图片和资产的实际落盘位置。

### 3. 工作流模板创建

- 从 ComfyUI 导入或捕获完整工作流。
- 识别正向提示词、负向提示词、Seed、宽高、Latent、LoRA 和最终输出节点。
- 暴露字段、语义标注、模板保存与提交前验证。
- 无输出节点、残缺工作流、跨标签画布污染和缺失节点的排查。

### 4. 生图参数选择

- Anima、Krea2、Niji、GPT Image/Banana 等提示词 Profile 的用途。
- Checkpoint、VAE、采样器、调度器、步数、CFG、降噪和二次采样。
- 最长边与画幅如何换算 Latent。
- 哪些参数继承工作流原值，哪些由剧情高潮或用户配置决定。

### 5. 节点知识库创建

- 从 ComfyUI 同步 `object_info` 与插件来源。
- 建立节点索引、Embedding 和 Reranker。
- 缺失节点识别、插件安装、版本更新和失败恢复。
- 大节点包、索引未就绪和本地代理导致失败时的排查。

### 6. AI 生成工作流

- 用户需要描述的目标、输入素材、模型与输出条件。
- AI 规划节点、端口连接、参数填写、预检和确认。
- 保存为模板并进行一次真实 ComfyUI 提交。
- Trace、错误节点和重新规划入口。

### 7. LoRA 同步与角色绑定

- 扫描 ComfyUI LoRA 目录并同步实际文件名。
- 保存触发词、建议权重和作者建议提示词。
- 角色名只作为本地“高潮人物→外貌→LoRA”关联键。
- single 模式的角色 LoRA 与风格兜底；multi 模式的默认风格与多角色串联。
- 如何从提交 Trace 和 ComfyUI 工作流确认实际加载的 LoRA，而不是只看提示词。

### 8. 自动剧情插画

- 剧情高潮、角色外貌、当前服装、动作、地点与构图的来源。
- 隐藏提示词 Profile、LoRA 元数据后注入和英文格式。
- `messageId + slotId` 原位回填、ComfyUI FIFO 和重新生成。
- 没有图片、错角色、错 LoRA、真人化、噪点、残留模板 LoRA 和后台任务不结束的排查。

### 9. 角色卡、世界书、预设与正则

- SillyTavern 格式导入。
- 角色字段、世界书触发、预设消息位置和正则作用域。
- 当前作品快照与源库解耦。
- 如何检查最终真正发送给模型的消息 manifest。

### 10. RAG、数据表、纪要与资产

- 普通 RAG、世界书、表格检索的职责区别。
- 状态表、通用表、T1-1/T1-2 独立纪要卡片和概览召回。
- 索引重建、手动补表和资产语义搜索。
- 图片不回灌对话历史的 Token 边界。

## v0.2 发布顺序

1. 冻结范围并完成真实角色、多角色 LoRA、重新生成、并发对话、刷新恢复验收。
2. 完成 README、详细教程、最终截图、演示视频、更新日志和已知问题。
3. 在 `main` 手动执行一次不发布的完整 Actions 构建。
4. 在干净 Windows 环境验证用户包；未真实验证的平台明确标记实验性。
5. 核对 Release 文件名、大小、SHA-256、合并脚本和启动/停止脚本。
6. 创建 `v0.2` 标签，等待 Runtime 与便携包工作流全部成功。
7. 下载正式 Release 资产做最终冷启动复验，再开始集中推广。

## 推广节奏

- 发布前：连续展示三类短内容——剧情一致性、角色 LoRA 自动插画、AI 搭建 ComfyUI 工作流。
- 发布日：GitHub Release、Bilibili/知乎和英文 ComfyUI、Local LLM、Stable Diffusion 社区同步发布。
- 发布后一周：整理安装失败与功能误解，优先发布 v0.2.1 稳定修复和 FAQ。
- 后续：用真实用户问题持续补教程，而不是只增加功能列表。

## 首月观察指标
