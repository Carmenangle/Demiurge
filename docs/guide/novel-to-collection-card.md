# 固化流程：小说转合集卡

> 把小说原文交给智能编造，按规范转为合集卡条目。
> 与[固化流程：批量生图](./curing-process.md)同源——都靠「智能编造 + 固化知识库」跑通；这一篇专注「文本转条目」。

本篇是应用内新手引导「固化流程：小说转合集卡」板块的 GitHub 阅读版。

## 1. 拖入小说文本并发指令

在「智能编造」对话里把小说原文粘进输入框，或直接拖入 `.md` / `.txt`（应用底部提示：可拖进输入框供 Agent 参考）。再明确一句「按固化知识库的合集卡规范处理为条目，并写入本作品世界书」即可——Agent 会自动读规范 §1（卡目录三文件形态、list 容器、5 字段、视觉画像契约的「角色卡·<名>」/「【外貌】/【身材】/【穿着】」锚点）。

要点：

- **限定范围**：尽量附带「按第一章出条」「每人一个外貌条目」之类的范围，避免一次性塞满整本小说。
- **写入位置**：默认落当前作品的 `repo.worldbook.json`（作品快照），不是源库世界书；想落源库另行说明。
- **底库支撑**：之所以 Agent 能直接照规范办，是因为 `data/agent_knowledge/固化02-小说转合集卡规范.md` 已经在「⚙ 设置 → 智能体 → 固化知识库」常驻注入——固化知识决定 Agent 怎么想。

## 2. 审计划与批准执行

Agent 贴出「已阅读计划：intent + steps + 预算」——steps 通常是「读文档 → 解析人物/场景 → 写条目」三步，预算显示条目数与 token 估算。出现「离审批」点「批准执行」即可；CPU/LLM 配额与路径域校验照旧生效。

要点：

- 计划里的 `steps` 数量是预算上限，不是必跑满——文档很短时 Agent 可能合并为两步。
- LLM 配额 ≤0 表示此条计划不调用 LLM，纯走规则解析；如果 LLM 配额 >0，那是要调用模型做语义判断，扣的是对话模型额度。

## 3. 去作品世界书核查条目

完成后到「资产管理 → 世界书」或「仓库绑定」里打开本作品的世界书，能看到 list 容器里的新条目：

- `constant: true` → 每轮常驻直注模型（注意 token 成本）。
- `constant: false` → 按 `keys` 子串命中 + 向量检索召回。
- **视觉画像条目**必须以「角色卡·<角色名>」开头、正文带【外貌】/【身材】/【穿着】三行首锚点——画布插画与生图链路的提取器依赖这个契约。

要反向验证知识库本身的内容，去「⚙ 设置 → 智能体 → 固化知识库」点开《固化02-小说转合集卡规范》（§1 字符与目录形态、§3.3 keys 质量）与《固化03-ST迁移规范》（§3.5 第二套固定流程）。要补条目或改写法，看完回来直接对 AI 说「按 §3.3 重写条目 7 的 keys」即可。
