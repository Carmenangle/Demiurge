# 固化流程：创建自己的固化流程

> 把一次跑通的智能编造任务固化为「可重放配方 + 知识规范」，之后同类目标整条重放。
> 示例贯穿本篇：**把当前作品的上下文（世界书条目、角色卡外貌、近期纪要）整理合并为一个设定文档**。

本篇是应用内新手引导「固化流程：创建自己的固化流程」板块的 GitHub 阅读版。
固化流程预设（配方）与固化知识库（规范）是两条互补机制：**固化知识决定 Agent 怎么想，固化预设决定 Agent 怎么快跑**。

## 1. 想清楚要固化什么，先完整跑通一次

在「智能编造」对话里，用大白话把任务讲清楚：**材料从哪读、合并成什么形态、落盘到哪**。示例指令：

> 「把当前作品世界书里所有角色条目、角色卡外貌与近期纪要，整理合并为一个设定文档，写到作品 docs/ 下」

Agent 会贴出计划（intent + steps + 预算），这类整理任务常含 `file.list_dir`（列出作品文件）→ `file.read_text`（读取各份材料）→ `doc.create_repo`（在作品 `docs/` 下创建 Markdown 文档）。确认无误点「批准执行」，durable / expensive 步骤照常走审批与配额。

要点：

- **必须完整跑通一次**：中途取消或失败不会产生可保留草稿；轨迹只在成功完成后固化为「草稿」配方。
- 意图越具体越稳：把输入材料、合并规则（按角色分组？按章节顺序？）、产物文件名一次交代清楚。

## 2. 点「保留」进入固化流程清单

跑通后，本次任务的步骤轨迹自动固化成一条「草稿」配方，对话末尾出现 `[[recipe:id|名称]]` 内联卡。点「保留」（或在「⚙ 设置 → 智能体 → 固化流程预设」里点保留）即列入清单；之后对话里出现同类目标，Agent 优先整条重放（`plan.instantiate_recipe`），durable / expensive 步骤照常走审批与配额。

要点：

- 不点保留的草稿不影响下次对话，可以放心跑着试。
- 已保留配方可在「⚙ 设置 → 智能体 → 固化流程预设」集中查看与删除。

## 3. 沉淀为固化知识规范（可选但推荐）

配方解决「怎么快跑」；想让 Agent 每次「怎么想」也一致，把规范写成 `.md` 放进固化知识库（`data/agent_knowledge/`，在「⚙ 设置 → 智能体 → 固化知识库」可见）。技能文档带 frontmatter：

```yaml
---
skill: curing-04-context-merge        # 唯一技能标识
whenToUse: 用户要求把多份设定/上下文整理合并为一个文档时
tools: [file.list_dir, file.read_text, doc.create_repo]   # 必须真实存在于能力注册表
---
```

正文写：适用与不适用、执行步骤、产物契约（合并规则、章节顺序、落盘路径）。smart 模式下会话只注入「技能名 → 触发描述」目录，模型命中场景才调 `knowledge.load_doc` 拉全文；在设置里勾选「常驻」可让关键技能每会话全量注入。

要点：

- `tools` 引用必须真实存在（`file.read_text` / `doc.create_repo` 等），测试合同会防漂移。
- 知识文档放进去即生效，不需要完整跑通任务；配方则必须跑通后才产生。

## 4. 验证与复用

验证：新开一轮对话，用同类意图（如「把这几份设定合并为一个文档」）触发，看 Agent 是否先读知识文档、再按配方重放。

复用：同类目标出现时整条重放省去逐步探索的 token；固化知识库与固化流程预设互相独立、互不替代——知识决定 Agent 怎么做，配方决定 Agent 多快做完。
